# 投放及素材搭建

## 核心原则

一轮投放只回答一个问题：**搜某类痛点关键词的人，看到针对这个痛点写的诉求，是否比看到通用工具话术更愿意行动。** 每一步都要产出固定的文件，下一步只能用上一步的产出，不能现场拍板。

## 输入

- idea-validation 的产出：`2-demand.md`（意图簇、月量、单次点击价）、`3-pains.md`（痛点频次与原话）、`4-competitors.md`（竞品广告话术）、`report.md`（最该先验证的假设）。
- 上一轮投放的 `learning-log.jsonl` 与报告（没有就写「无」）。

没有痛点证据时，假设过不了合格检查，本轮只能做**冒烟测试**：检查广告审核、触发的搜索词、追踪链路，不判输赢。先建议用户跑 idea-validation。

## 六步与产出（按顺序，不可跳步）

| 步 | 做什么 | 产出（存进本轮目录） |
|---|---|---|
| 1 复盘 | 读上轮学习记录与报告：我们当时相信什么、结果是什么、学到什么、下一步定了什么。上轮不是对照实验时，按 ad-hypothesis-testing「不是对照实验的投放」做描述性复盘 | `1-retro.md`：每条假设一行，结论原样照抄，不重新解读 |
| 2 人群与设备 | 按设备、地区、时段、新老用户、内部流量逐项拉自家转化数据，列表给用户，**等用户确认后**再往下（见下节） | `2-audience.md`：每个维度的数据、选择、对可投放量的影响、确认人与日期 |
| 3 假设 | 按模板写假设，过合格检查（见下） | `3-hypotheses.md` |
| 4 可行性 | 对每条假设运行 ad-hypothesis-testing 的 `plan`，`--confirmatory-count` 填本轮确认性假设条数，`--daily-units` 用第 2 步缩减后的量；预算不够或 `fits_window: false` 时只能减假设、放大可检出倍数（取 `achievable_mde_lift_ratio`）或降为探索性。实验周期限定 1–3 个完整日 | `4-feasibility.json` |
| 5 实验策略 | 按 `strategy.md` 填策略单：分流、对照、不变项、指标层级、国家、预算、决策映射 | `5-strategy.md` + 登记草稿 `prereg.json` |
| 6 素材 | 按策略单的规格写测试与对照广告和落地页首屏，见 `creative.md` | `6-creatives.md` |

第 6 步完成后，交给 ad-hypothesis-testing 锁定登记。

## 人群与设备选择（第 2 步，投放前必须确认）

不预设任何默认值：每一轮都要用自家数据重新看，再由用户拍板。

| 维度 | 要看的自家数据 | 要做的选择 |
|---|---|---|
| 设备 | 按电脑、手机、平板拆分的注册、付费人数、付费率、客单价（同一产品线、最近一个完整周期） | 投哪些设备；不投的设备出价调整设为 -100% |
| 地区 | 各国的付费率、客单价、单次点击价 | 投哪些国家；按单价档分系列；只投「所在地」 |
| 时段 | 按小时、按星期几的转化分布 | 是否限时段投放 |
| 新老用户 | 搜索人群里已注册用户的占比 | 是否排除已注册或已付费用户 |
| 内部流量 | 团队与测试账号的 IP | 排除哪些 IP |

数据来源：自家业务库只读查询（注册、付费、首个浏览器标识判断设备，剔除测试账号，「未知」单独列出），以及 Google Ads 接口按 `segments.device`、`user_location_view`、`segments.hour` 拆分的历史投放数据。

规则：
- 每个维度写清数据来源和样本量；样本太小或「未知」占比高时如实写明，不要硬下结论。
- 写出每个选择让可投放量减少多少（例：只投电脑端，点击约剩原来的 37%），并带进第 4 步。
- 不同产品线结论可以不同（例：同期产品 A 手机端 0 付费，产品 B 手机端付费率最高），不能拿一个产品的结论套另一个。
- 把表格发给用户，拿到明确确认后才进入第 3 步；确认人和日期写进 `2-audience.md`，再填进登记的 `audience` 字段。
- 「随便」「你定」「照旧」不算确认：把你的建议和依据列出来，请用户对每个维度回答是或否。用户给了上线日期也不能跳过这一步；来不及就说明会晚多久。

## 假设模板（第 3 步）

> 基于【idea-validation 的证据，含数字】，我们认为：在【第 2 步确认的设备与地区】上，搜【意图片段】的用户，看到【针对痛点 X 的诉求】，比看到【通用工具话术】，在【指标：点击率 / 落地后某行为】上更高（或更低）。最小有意义的差距是【倍数】，否则我们认为这个诉求不值得作为主张。

**合格检查**：以下任何一项不满足就退回重写。
- 人群是一个具体的意图关键词组，不是「用户」「市场」。
- 只改一个变量：只有广告诉求不同。
- 指标能在本轮投放里直接测到；「需求是否真实」「会不会付费」这类问题要拆成可测的行为。
- 写了最小有意义的差距，而且是开投前写的：先请用户给出业务上值得改主张的最小倍数（没给就问，不要自己假设），第 4 步 `plan` 算不下来时只能改成 `achievable_mde_lift_ratio`，并在假设里写明是被预算或周期倒逼的。
- 证据来自 idea-validation 的文件，能指出具体数字。

## 缺东西时怎么办

| 情况 | 做法 |
|---|---|
| 没有上一轮学习记录 | 第 1 步写「无」，照常往下 |
| 没有痛点证据 | 只做冒烟测试，不判输赢；建议先跑 idea-validation |
| 没有该关键词组自己的基线 | 先用 Google Ads 接口读该组或对照组的历史点击率；读不到就用账户整体值代替，假设降为探索性。用账户整体值时只取谷歌搜索网络（不含合作伙伴）、同类匹配方式的数据，并写明差异 |
| 预算只够探索 | 作为冒烟测试或探索性筛选来跑，结论只决定下一轮测什么 |
| 想同时比较多个痛点 | 每个痛点各配一组意图关键词和一条通用对照，各自一条假设；同一组关键词下比较多个诉求是多臂实验，不在本技能范围 |
| 某个痛点找不到自己的搜索关键词组 | 这个痛点本轮不进广告实验，写进 `3-hypotheses.md` 的「暂缓」并说明原因 |
| 痛点是大家都在说的卖点 | 它和通用话术区分不开，不能作为测试诉求 |

## 决策映射（第 5 步必须写完）

对 ad-hypothesis-testing 的每种结论，事先写好行动，并标出对应的下一步类型（`act` 按结论行动、`confirm` 做确认实验、`redo` 修复后重做）。这张表原样填进登记的 `decisions`，随登记锁定，学习记录的下一步由它自动生成：

| 结论 | 要事先写的行动 | 下一步类型 |
|---|---|---|
| 测试诉求显著更好 | 改哪些文案或落地页 | `act` |
| 通用话术显著更好 | 换主张还是换人群 | `act` |
| 统计上脆弱 | 是否值得做确认实验 | `confirm` 或 `act`（放弃） |
| 功效足够的中性结果 | 降优先级还是放弃 | `act` |
| 功效不足 | 加样本做确认还是放弃 | `confirm` 或 `act`（放弃） |
| 实验无效 | 修什么后重做 | `redo` |
| 探索性筛选通过、探索性筛选通用话术更好 | 下一轮确认实验测什么 | `confirm` |

## 常见错误

| 错误 | 改正 |
|---|---|
| 先做素材再定策略 | 素材在第 6 步，按策略单规格写 |
| 测试广告讲产品功能 | 第一句点出用户认得出的问题，用 `3-pains.md` 的原话 |
| 拆很多组，每组只有几次点击 | 第 4 步先算预算能撑几条假设，同一批人的不同阶段合并成一组 |
| 通过标准拍脑袋（「提升 25%」「胜出概率 90%」） | 只用 `plan` 算出的样本量和可检出倍数 |
| 不同单价国家混在一个系列 | 按单价档分系列，分别登记 |
| 用账户整体点击率当基线 | 用同一关键词组或对照组的历史数据 |
| 用 `[品牌词]` 否定完全匹配挡导航词 | 改用否定词组 `"品牌词"`，变体逐个列出 |
| 开着 AI Max 或自动应用的建议测文案 | 建系列时关闭，开投前读回设置 |
| 周期拉得很长才出结论 | 周期限定 1–3 天，靠集中每日预算和放大可检出倍数来换取速度；报告写明覆盖不到完整一周 |

规则依据是谷歌广告帮助中心与 Google Ads API v25 文档（自定义实验、广告变体、匹配方式、AI Max、虚假陈述政策），核对于 2026-10；谷歌会改规则，投放前以官方页面为准。
