# 付费意愿专轮（第 6 步）

付费意愿要从**已经发生的花钱行为**里找，不从「我想要」「我愿意付」里找。研究显示，嘴上说的价格平均是真实付款的 1.35 倍（同口径元分析的中位数）到约 3 倍（宽口径），所以口头表态只能当上限。

## 付费证据阶梯

| 级别 | 含义 | 公开数据里的样子 |
|---|---|---|
| L0 | 只有关注 | 点赞、收藏、「想要」、搜索量 |
| L1 | 嘴上说愿付 | 「我愿意付 $X」、问卷价格 |
| L2 | 价格锚点存在 | 竞品有定价页、套餐结构（**不能证明有人付钱**） |
| L3 | 付费的旁证 | G2 认证用户（Verified Current User）的评价数、应用收入估算、竞品招聘、网页存档显示定价页存续多年且涨价 |
| L4 | 已经在为替代方案花钱 | 「我每月付 X 给 Y」的帖子、外包平台上为这件事开的标价单、GitHub 悬赏或赞助、顾问收费页 |
| L5 | 第三方核验的同类收入 | TrustMRR、Indie Hackers 的 Stripe 认证收入页上同类产品的收入 |
| L6 | 对本产品的付费承诺 | 预售、押金候补、填卡的假门测试、付款 |

**评分规则**（N3 付费意愿按最高级别机械给分，不得上调）：只有 L0–L1 给 1 分；有 L2 给 2 分；有多条相互独立的 L3–L4 给 3 分；有 L5，且价格抱怨或变通办法成本能支撑目标价位，给 4 分；5 分只给做过 L6 实验的产品。只用公开数据，最高 4 分。

报告必须原样写这句话：「以上证据证明的是这个品类里存在付费行为，而不是用户会为本产品付费；验证后者需要做（具体实验），通过门槛为（事先写定的数字）。」

## 去哪找

| 级别 | 来源 | 做法 |
|---|---|---|
| L5 | [TrustMRR](https://trustmrr.com)、Indie Hackers 产品收入页 | 网页搜索「site:trustmrr.com <品类词>」或在站内搜同类产品，记产品名、核验收入、价格、上线时间 |
| L3 | 网页存档 | 免费：`https://web.archive.org/cdx/search/cdx?url=<竞品域名>/pricing&output=json&fl=timestamp,statuscode&collapse=timestamp:6` 列出历年快照，再打开 `https://web.archive.org/web/<时间戳>/<竞品域名>/pricing` 对比价格和套餐变化 |
| L3–L4 | 竞品评价 | G2、Capterra、应用商店、Chrome 商店、Product Hunt；G2 认证用户已付费，其他平台降一级使用 |
| L4 | 社区原话 | 第 4 步编码时 `wtp_level` 标 L4 的片段：「I pay」「我每月付」「为此订阅了」 |
| L4 | 外包平台 | 网页搜索 Upwork、Fiverr 上为这件事（或它的变通办法）开的单和标价 |
| L4 | GitHub | 悬赏（如 issue 里的 bounty 标签）、赞助、为此维护的分支 |
| L3 | 应用收入估算 | 不同供应商相差 20–50%，只看量级 |

## 竞品差评挖掘

选 3–5 个竞品，只取近 12 个月的评价，每个 50–100 条。1–3 星找痛点、换用原因和价格抱怨；4–5 星找必须保留的功能。价格抱怨分四类，形态比数量更有信息量：

1. 「涨价后我们换到 X」：暴露真实的价格弹性；
2. 「为了某个功能被迫升级高档套餐」：这个功能有溢价空间；
3. 「按席位收费很不划算」：计价单位错配；
4. 「值这个价」：反向证据，说明现价被接受。

同时抽出评价里提到的其他竞品名，补进竞品清单。

## 变通办法成本 → 价格上限

每月变通成本 ≈ 单次耗时 × 每月次数 × 时薪 × 人数 + 直接订阅或外包支出 + 预期失败损失。

- 输入来自帖子原话（`workaround_cost` 字段）；时薪取外包平台同类任务的公开标价，标为假设。
- 给区间，不给单点；写明有多少条帖子真的给出了数字（通常很少），且发牢骚时自报的耗时偏高。
- 从业者经验是定价拿走量化收益的 10–25%，这是经验，不是研究结论。
- 竞品锚点取 3–5 个竞品的入门档和主力档；某竞品涨价后仍在 TrustMRR 或 G2 上持续增长，说明这个价位被接受。
- 报告里把「有据的锚点价格」和「推论的建议价格」分开写。

## 用户让你给定价时

用户说「定价请调研后给建议」，就按上面的锚点和变通成本给建议区间，明确写「建议」，收入模型里 `price_per_month` 的出处写「建议区间，依据见 6-wtp.md」。用户自己给了定价，就用用户的，并对照锚点指出偏高或偏低。
