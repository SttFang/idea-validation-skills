# 编码与饱和（第 4 步）

把原话变成可计数、可核对的证据。模型按固定编码本归类很可靠（与人一致约 93–96%），但让它自己归纳主题时只有约三成与人一致，还会出现约 1% 的编造引文。所以流程把**归纳**和**归类**分开，并且每条原话都要逐字核对。

## 1. 试点归纳，然后冻结编码本

1. 先取 50–100 个片段作为试点批（来自至少 2 个平台、10 名以上作者）。
2. 从试点批归纳编码本，每个代码写：名称、一句话定义、纳入例子、排除例子。代码描述的是**用户想取得的结果或遇到的阻碍**，写成「方向 + 指标 + 对象 + 情境」，例如「减少在第二台电脑上重新配置 agent 规则的时间」，**不写解决方案**。
3. 编码本必须包含两组预设代码，保证能找到反对证据：
   - 反对类：`免费方案够用`、`不需要`、`官方会做`、`隐私或信任顾虑`、`只是好奇`；
   - 付费类：`已在付钱`、`嫌贵`、`换用原因`、`求免费`。
4. 冻结编码本，写进 `codebook.md`，后面只归类、不新增；确需新增时记一笔「第 N 批新增」，这正是饱和度要统计的东西。

## 2. 每条片段的字段（写进 evidence.jsonl）

| 字段 | 取值 | 怎么判断 |
|---|---|---|
| `id`、`market`、`platform`、`community`、`url`、`author`、`date`、`engagement` | — | 原始数据里照抄；`market` 填「中文」或「英文」，统计时用 `--market` 分开 |
| `quote` | 原文片段 | 只能从原文**挑选**，不改写、不翻译；翻译另写 `quote_zh` |
| `source_file` | 原始数据文件路径 | 用于逐字核对 |
| `codes` | 编码本里的代码列表 | 一个片段可以有多个 |
| `segment` | 人群 | 角色、团队规模、技术栈、是否有预算权，能看出多少写多少 |
| `force` | 推力 / 拉力 / 焦虑 / 惯性 | 推力：现状让人难受；拉力：新方案的吸引；焦虑：对换用的担心（迁移、隐私、锁定）；惯性：「现在这样也能用」 |
| `stage` | 初念 / 被动寻找 / 主动寻找 / 决定 / 使用 | 吐槽不求解 → 初念；「大家怎么处理」→ 被动寻找；「X 的替代品」「X 对比 Y」→ 主动寻找；「准备买 X 有什么坑」→ 决定；「从 X 换到 Y」→ 使用 |
| `severity` | 0–5 | 痛点阶梯：0 无关；1 有问题；2 知道有问题；3 在主动找解法；4 自己拼了临时方案（脚本、表格、手工流程）；5 有或能拿到预算、已经花钱 |
| `wtp_level` | L0–L6 | 见 `wtp.md` 的付费证据阶梯 |
| `workaround_cost` | 可选 | 帖子里给出的耗时、频次、人数、花费原文数字 |
| `round` | 第几轮取数 | 用于饱和度 |

「从 X 换到 Y」的帖子最接近换用访谈，里面有已经完成的决定，要优先挖。一个需求簇里处在「主动寻找」及之后阶段的作者越多，需求越强。频率单独记，权重低于紧迫性：付费意愿由紧迫程度驱动，不由使用频率驱动。

## 3. 双轮编码与核对

- 至少 20% 的片段做第二轮独立归类：交给一个**新开的子代理**（只给编码本和片段原文，不给第一轮结果和你的结论），每个代码报告一致率；自己重编一遍不算独立。第二轮也要给到整帖上下文，只给摘录会让「认知阶段」系统性偏向「初念」；某个代码一致率明显偏低（例如低于 0.6 的 κ 或 AC1），就改写它的定义后重做。
- 每轮编码一次只做一个决定（例如这一轮只判 `stage`），不要一次判所有字段。
- 运行 `python3 scripts/evidence.py verify evidence.jsonl`：原话在原始数据里找不到的，整条删除，不能进报告。

## 4. 饱和度：什么时候可以停

按独立作者分批（默认每批 10 人），统计每批带来的新代码。运行 `python3 scripts/evidence.py saturation evidence.jsonl --market 英文`（中英文分开跑）：至少 5 个满批，且最近两个满批的新代码占已有代码的比例都不超过 5%，才算饱和；不满 10 人的最后一批不参与判断。片段要按取数顺序写入，不要按场景排序后再写，否则会出现假饱和。

- 批次按作者算，不按评论算，否则一个高产用户会制造假饱和。
- 一条帖子的信息量远低于一次访谈，需要的作者数比访谈研究多。
- 分平台、分人群各看一次；某个人群没饱和，关于这个人群的结论就降一级。
- 没饱和又没预算继续时，可以停，但报告里写明，并把相关结论标为「待验证」。

## 5. 成立门槛

运行 `python3 scripts/evidence.py stats evidence.jsonl` 得到每个代码的独立作者数、社区数和最高付费证据级别。一个需求要写成「成立」，默认至少 5 名独立作者、2 个社区（可调默认值，没有文献给出这个数字）；不够就写成「存在迹象」。

## 6. 引用的边界

内部证据库保留原文、链接和作者供核查；对外分享的报告去掉用户名、只用短摘录。公开帖子逐字引用很容易被搜回原帖，涉及健康、财务等敏感话题和小社区的内容要改写。永远不要根据抓取到的内容去联系个人。
