# 广告诉求实验验证

## 核心原则

结论只能来自**开投前锁定的登记**加**脚本算出的检验**。看过数据之后才定的门槛、检验方法、分组、口径或停止时机，一律无效。

## 在经营流程里的位置

想法验证（idea-validation：拓词 → 核量 → 原话 → 竞品 → 算钱）之后，投放及素材搭建（ad-campaign-build：复盘 → 人群与设备 → 假设 → 可行性 → 实验策略 → 素材）产出**登记草稿**；本技能负责：可行性计算（与 ad-campaign-build 共用）→ 选定检验方法 → 登记锁定 → 投放纪律 → 可信度检查与检验 → 按登记下结论 → 学习记录。没有登记草稿时，先让用户走 ad-campaign-build，不要现场编假设。

## 流程

1. **可行性**：每条假设运行
   `python3 scripts/ab_stats.py plan --baseline <基线比例> --lift <最小可检出倍数> --budget <该假设预算> --cpc <单次点击价> --daily-units <每天两组合计单位数> --confirmatory-count <本实验确认性假设条数> --design-effect <登记的 design_effect.floor> [--metric conversion]`
   - `--design-effect`：点击率（展示为单位）填登记的设计效应下限，没有历史数据用 1.25；转化（访客为单位）填 1。样本量和预算都按它放大，和锁定时一致。
   - `--confirmatory-count` 必填真实条数：多条确认性假设时 α 按条数分摊，样本量随之变大，和锁定时的算法一致；漏填会在锁定时被判功效不足。
   - `--daily-units` 是**这条假设（这一组关键词）每天两组合计**的量，按登记人群（设备、地区）过滤后、按每日预算实际能买到的，取两者中较小的；不知道就先按关键词规划工具的量乘设备占比估，写明出处。
   - `feasible: true` 且 `fits_window: true` → 继续。登记的 `budget` 填实际设置的累计花费上限（不低于 `required_budget`，不要平摊总预算）；上限低于 3 天能花掉的钱时，终点通常是预算花完，填 `budget_exhausted`。输出里的 `method` 是按样本规模选定的检验方法。
   - 否则只给用户三个选项：每天量提高到 `min_daily_units_for_window`（加预算只在量没到关键词上限时有用）；把倍数放大到 `achievable_mde_lift_ratio`（已同时考虑预算和 3 天周期）；或该假设标 `role: exploratory`。
2. **登记与锁定**：从 `preregistration-template.json` 填写：`budget`、`cpc`、`window_days`（1–3 天）、设计效应规则 `design_effect`（见下方「同一用户重复看到广告」）、护栏阈值 `guardrails`（由用户确认的 0–1 数值，技能不给默认值；两组都出现过的访客占比上限 `both_arms_visitor_share_max` 必填，投欧洲经济区、英国、瑞士时 `consent_rate_diff_max` 也必填，缺了锁定会拒绝），ad-campaign-build 第 2 步经用户确认的 `audience`（设备、地区、只投所在地、时段、排除项、依据、确认人、确认时间），以及ad-campaign-build 第 5 步的决策映射 `decisions`（八种结论各写 `action` 和 `step`，缺一种锁定就拒绝）。登记中期检查时同时写 `interim_after_days`（第几天结束后查）。`planned_n_per_arm` 填 `plan` 的 `n_per_arm`。锁定前人工确认：基线来自**同一关键词组或对照组**的历史数据；不同单价档的国家已分成不同假设。运行 `python3 scripts/ab_stats.py lock prereg.json --out prereg.locked.json`（失败时不写文件、打印原因），锁定文件里的 `methods` 就是每条假设锁定的检验方法。看 `warnings` 和 `feasibility`：确认性假设出现 `feasible: false`、`underpowered_registration: true` 或 `fits_window: false` 时回到第 1 步（不处理会自动降为探索性）。同一批流量上的下游指标假设填 `traffic_from: <上游假设编号>`，共用预算。**开投前把锁定文件提交到 git**，提交时间就是事先登记的证据；提交号填进结果文件的 `git_commit`。
3. **投放纪律**：开投时间写进结果文件的 `launch_at`。期间只查数据质量（是否拒登或受限、预算是否受限、搜索词是否一致、无效点击、追踪），不查看效果数据、不停、不改预算比例。
   - **中途查看效果数据**，指的是终点之前去看点击率、转化率或哪组领先，并据此决定停、继续或改设置。只有登记了 `interim_looks: 1` 才能做一次中期检查，而且只能在登记的 `interim_after_days` 那天结束后做（别的天数脚本拒绝），门槛是 p < 0.001（Haybittle–Peto），达到才允许提前停；没达到就继续投到终点。
   - 有人在未登记的情况下查看了效果数据，如实填 `unregistered_views`（次数）；查看后提前停了，填 `stopped_early: true`（结论自动降为探索性）。
   - **终点**：登记的结束日期（`window_days` 满），或累计花费达到 `budget`，以先到者为准（预算先花完时填 `budget_exhausted: true`）。终点之前做终点分析会被拒绝。样本量只在终点检查，不作为提前结束的条件，也不能事后挑截断日：`plan` 算出 2 天够、登记了 3 天，也投满 3 天。
   - 样本量按**两组合计**检查（合计 ≥ 2 × `planned_n_per_arm`）：50% 分流下两组展示数不会正好相等，轻微不等不影响功效，严重不等由失衡告警处理。
   - **中期检查**的结论只有两种：达到 p < 0.001 可以停（结论按终点同样的规则给出），或「继续投到终点」。后者不是实验结论，不要写进报告的结论栏，也不写学习记录（脚本会拒绝）。
   - `unregistered_views` 按「有人看了效果数据的次数」记，同一天多人看算多次；拿不准就往多记。
4. **分析**：每组计数从接口 `experiment` 资源取（`metrics.impressions`、`metrics.control_impressions`、`metrics.clicks`、`metrics.control_clicks`，按 `segments.date` 分天填进 `daily`），或按 `campaign.experiment_type` 分系列查。点击率假设还要填每组的访客点击直方图和 gclid 关联率（见下方「同一用户重复看到广告」）。尽量在结束后隔一段时间再取最终数并填 `retrieved_at`（无效点击和转化会回溯调整）。按 `results-template.json` 填数据（`days_run`、`quality_flags`；`daily` 行数必须等于 `days_run`，按天合计必须等于总数，否则分析拒绝）。护栏数值（搜索词重合度、无效点击率、同意率差异）由人对照登记阈值判断，超阈值就打对应标记。先运行 `python3 scripts/ab_stats.py analyze prereg.locked.json results.json` 看结论，再带上学习记录运行一次：`... --log learning-log.jsonl --lesson "<一句话，只能复述脚本结论>"`。每条假设的下一步由脚本按登记的 `decisions` 自动填，不能现场改。脚本输出里的「注意」（缺 git 提交号、取数太早）要处理后再定稿。
5. **报告**：照抄脚本表格，按「报告格式」写结论；学习记录随报告一起提交。

## 统计方法选择（登记时由脚本按样本规模选定并锁定，不可现场更改）

| 情况 | 方法 | 依据（文献见文末「方法出处」） |
|---|---|---|
| 最小期望格子数 < 5，或每组样本低于正态近似门槛 | **Barnard 精确检验**（双侧）+ Newcombe 区间 | 小样本下正态近似不可靠；Barnard 比 Fisher 功效高且守住 α |
| 每组样本 ≥ 正态近似门槛（Kohavi 偏度规则 n > 355·s²，点击率 6% 时约 4,900） | **两比例 z 检验**（双侧，合并方差）+ Newcombe 区间 | 正态近似成立 |
| 多条确认性假设 | **Holm** 校正 | 控制家族错误率，用于「已验证」的结论 |
| 探索性假设 | **Benjamini–Hochberg** 校正，单独报告 | 控制错误发现率，只用于筛选下一轮测什么 |
| 登记了一次中期检查 | **Haybittle–Peto**：中期 p < 0.001 才停，终点仍按 α = 0.05 | 提前停只在极强证据下发生，终点几乎不损失功效 |
| 随机单位是用户、检验单位是展示 | 按第一方访客点击分布算**设计效应**，计数除以它（Kish 有效样本量）后用上面锁定的方法检验；结论只看校正后的 p 值。不校正显著、校正后不显著，判「统计上脆弱」 | 同一用户的多次展示相关，按展示检验会低估方差（Bakshy & Eckles 2013；Deng 等 2018）。按天方向只作描述，3 天只有 3 个聚类、天也不是随机单位，不能当修正 |
| 下游行为（转化） | 单位用**去重后的落地访客**，同样按上面的规则选方法 | 分析单位更接近随机单位 |

## 同一用户重复看到广告（点击率假设必做）

1. **开投前的工程前提**：落地页在服务端记录 `gclid`、第一方访客编号、到达时间、`v=test/ctrl`；排除登记里的团队 IP 和已登录员工。没有这条链路时只能走第 4 条的区间回退。
2. **登记**：`design_effect` 写 `source: first_party_click_histogram`、`floor`（规划用下限，没有历史数据用 1.25，积累两三轮后改用历史值的较高分位数并写明出处）、`band`（关联率不够时用的区间，默认 `[1.0, 1.5, 2.0]`）、`min_match_rate`（gclid 关联率门槛，由用户确认，参考 0.7）。
3. **终点**：每天按日期拉 `click_view`（`gclid`、`campaign.id`），和落地记录按 `gclid` 关联。每组填三样：`test_histogram` / `control_histogram`（`{"点击次数": 访客数}`）、`gclid_match_rate`（`{"test": 关联率, "control": 关联率}`）、`visitors_in_both_arms`。脚本按组分别算 `ΣK²/ΣK`，每组取它和 `floor` 中较大的作为该组设计效应，各组计数除以各自的值（重复点击出在哪组，就只放大哪组的方差）。校正后有效样本低于功效要求时，未检出差异判「功效不足」，不判中性。
4. **关联率不够或没有直方图**：改用 `band`，表里列出每个设计效应下的 p 值，结论按区间上端判（部分关联算出的值比上端还大时取更大的，缺数据不能换来更轻的校正）；不校正显著、上端不显著的判「统计上脆弱」。
5. 两组都出现过的访客占比超过 `both_arms_visitor_share_max`：判实验无效（分流被破坏）。没有直方图时要填 `visitors_total` 作分母，否则分析拒绝。
6. 转化假设（单位是去重访客）不需要校正，脚本自动按 1 处理。
7. 局限照写：展示次数的重复观测不到，只校正了点击的重复；设计效应是几十个访客算出的估计值，本身有不确定性，没关联上的点击假设和关联上的一样；Barnard 的「精确」只在设计效应已知时成立。

## 其他默认

| 项 | 默认 | 理由 |
|---|---|---|
| 周期 | 1–3 个完整日 | 实验要足够短；代价是只能检出更大的差距、覆盖不到完整一周，报告里写明 |
| 分流 | 谷歌广告实验或广告变体，按 cookie 50:50 | 同广告组「不优化」轮播时谷歌仍按广告质量给排名，只能做探索。50% 只保证两组进入同样多的竞价；`split_method` 在界面确认后人工填写 |
| 方向 | 双侧，α = 0.05 | 「通用话术更好」也会改变策略 |
| 样本比例失衡 | p < 0.01 只告警，查原因 | 实验模式下展示数受排名影响 |
| 实验无效 | 硬性事实触发：任一组拒登或受限（含 Eligible (limited) 和限量投放通知，**哪怕只有几小时**：受限期间两组进入的竞价不同）、单组预算受限、搜索词分布或无效点击率超过登记阈值、追踪中断、出现 AI Max 匹配类型、未登记的设置变更 | 直接破坏可比性 |
| 取数时间 | 结束后至少等 3 天再取最终数，填 `retrieved_at` | 无效点击和转化会回溯调整 |
| 平台显著性 | 谷歌界面的星号和区间只作交叉参考 | 界面方法不同，区间默认显示 80% |

## 锁定有告警但已经开投

不改登记（改了哈希就对不上）。照常投到终点、照常分析；脚本会把受影响的确认性假设降为探索性，报告里写明原因，下一步用 `plan` 规划确认实验。

## 不是对照实验的投放（只有一版广告、按国家或时间分系列）

没有对照组、没有随机分流，就**没有可以检验的假设**：不同国家、不同日期的系列之间差在人群、单价、时段和排名上，任何差距都说不清来自哪里，不跑 `analyze`，也不补登记。只做描述性复盘，交给 ad-campaign-build 第 1 步，用途只有三个：
所有比例都附 95% 区间（`python3 -c "import scripts.ab_stats as m; print(m.wilson(x, n, 0.95))"`，在 `scripts` 目录下运行时去掉 `scripts.`）；两组比例的差附 Newcombe 区间，可以给 p 值，但只说明样本能不能区分，不能写「差不多」「更好」这类结论。拿去当下一轮基线时，同时用区间下端跑一次 `plan` 作保守情况。
1. **数据质量**：地区泄漏（所在地之外的展示占比）、设备分布、搜索词与意图的相关性、追踪与归因是否通。
2. **下一轮的规划输入**：同一关键词组的点击率作为基线（写明来自非实验投放）、每天可买到的展示数、单次点击价，带进 `plan`。
3. **下一轮该测什么**：只能提出假设，不能当作已经证明。

## 事后补登记（已经投完、没有登记）

如实登记实际做法：`role: exploratory`，`split_method` 填真实分流方式，`launch_at` 填真实开投时间，基线不得取自本次实验的数据。脚本会把结论降为探索性。对外只能说「探索性信号」，不能说「已验证」；接着用 `plan` 规划一个确认实验。

## 报告格式

每条假设只能是脚本给出的结论之一：测试诉求显著更好；通用话术显著更好；统计上脆弱（待确认实验）；功效足够的中性结果（写明能检出的最小倍数）；功效不足（不下结论）；实验无效（不下结论）。探索性实验里的「更好」只能写成「探索性筛选通过，待确认实验」；「统计上脆弱」的含义是：信号可能只是少数人反复点击造成的；探索性实验里出现时，下一轮不优先测。

报告结构固定：登记摘要（含哈希、git 提交、分流方式、锁定的检验方法、设计效应规则）→ 脚本结果表 → 每条假设一句结论 → **结论适用范围**（只对登记的设备、地区、时段和这几天成立；点击率更高只说明诉求更吸引点击，不说明用户愿意付费）→ 局限（已按第一方点击分布校正同一用户重复（写明设计效应和来源：实测或区间上端），展示次数的重复没有观测到、未计入；两组广告评级不同带来的位置效应；平台对两组人群的选择可能不同；周期短、覆盖不到完整一周；探索性原因）→ 下一步（每条假设照抄登记的 `decisions`：`act` 按结论行动，包括放弃或降低优先级；`confirm` 按 `plan` 加样本做确认实验；`redo` 修复问题后重做）。

可检出倍数是被预算或周期倒逼放大的，报告里写明「中性结果只代表没有 X 倍以上的差距，不代表没有差距」。无效或缺数据的确认性假设仍留在 Holm 家族里（按 p = 1 计），这是有意的保守做法。

## 禁止的做法

| 想法 | 为什么不行 |
|---|---|
| 「各组都不显著，合并起来看看」 | 事后合并是新检验，脚本会拒绝未登记的假设 |
| 「先看数据再决定用哪种检验」「差一点，放宽到 0.1」 | 方法和 α 锁定后不能改，改了分析拒绝执行 |
| 「不显著但方向向好，先押注」「样本不够也给个倾向」 | 未检出差异不能推出方向 |
| 「第 1 天领先 3 倍，提前停」 | 没登记中期检查就不能据此停；登记了也要 p < 0.001 |
| 「样本够了，就算到第 2 天为止」 | 终点只认结束日期或预算花完，不能事后挑截断日 |
| 「频率检验和贝叶斯胜出概率都报一下」 | 只用登记的方法下结论 |
| 「没时间登记，先投了再补」 | 补登记的实验自动降为探索性 |

## 常见错误

- 报告里的点击和点击率已剔除无效点击，主指标不用再扣。
- 点击率用点击数当分母（应为展示数）；下游转化用点击数当分母（应为去重后的落地访客数，按网址参数 `v=test/ctrl` 分组）。
- 基线用账户整体点击率：应用同一关键词组或对照组的历史数据，并写明出处。
- 不同单价档的国家混在一起：要分系列、分假设登记。

脚本输出只覆盖登记摘要的一部分和结果表；方法说明、每条一句结论、局限、下一步要人工按上面的结构补齐。多条确认性假设时，区间按 α/条数 计算，可能跨 0 而 Holm 判显著，结论以 Holm 为准。

脚本测试：在本技能目录运行 `python3 -m unittest scripts/test_ab_stats.py`。
